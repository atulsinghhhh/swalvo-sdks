Phase 3 chat: offline outbox, event catch-up, inbox, moderation, push, pins, search and a React UI kit.

- **Offline outbox, on by default.** Every `sendMessage()` goes through `chat.outbox`. A send the connection drops stays `pending` and is re-sent on reconnect with its original `clientMessageId`, so it is stored once however many attempts it takes. A send the server refuses goes to `failed` and waits for `outbox.retry(id)` or `outbox.cancel(id)`. The promise still settles on the first attempt: a connectivity rejection now carries `error.queued === true` and `error.clientMessageId`, meaning "pending, not lost". New `outboxChanged` event. Persist across reloads with `outbox: { storage: new LocalStorageOutboxStorage() }` or your own `OutboxStorage` (two methods; an AsyncStorage adapter is a few lines). `outbox: false` restores the old reject-and-forget behaviour.
- **Edits, deletes, reactions and moderation are caught up after a reconnect**, not just messages. Conversation events carry an `eventSeq`; the SDK applies them in order, drops duplicates, backfills live gaps from `GET …/events` after a short grace period (`gapFillDelayMs`, default 300 ms), and on `EVENTS_EXPIRED` re-reads history and emits the new `resync` event. `RecoverySummary` gains `events` and `resynced`.
- **`seq` on messages** (a string; compare with the new `compareSeq()`), and `afterSeq` / `beforeSeq` on `messages.list()`.
- **Inbox.** `chat.queryMyConversations({ limit, cursor })`, and `chat.inbox`, a live store (`load`, `loadMore`, `refresh`, `subscribe`, `getSnapshot`) whose unread counts follow incoming messages and read marks, de-duplicated by `seq`. It joins up to `watchLimit` (15) listed conversations to receive their messages.
- **Moderation.** `chat.moderation.block/unblock/listBlocks/flagMessage`, moderator `ban/unban/mute/unmute` with optional durations, `getMyState(room)`. New events `memberBanned`, `memberUnbanned`, `memberMuted`, `memberUnmuted`, and `removedFromRoom` (`reason: 'BANNED'`) after which the SDK stops rejoining that room. New error classes `SwalvoModerationError` (`MUTED`/`BANNED`/`BLOCKED`), `SwalvoSlowModeError` (`retryAfterSeconds`), `SwalvoMessageBlockedError` (`reason`); `SwalvoRateLimitError` gains `scope`.
- **REST errors now map to the typed classes.** HTTP error bodies report the canonical `RAVEN_*` code in `code` and the chat code in `legacyCode`; the SDK used to read only `code`, so a `RATE_LIMITED` over HTTP surfaced as a plain `SwalvoChatError`. It now prefers `legacyCode` (falling back to `code` with the `RAVEN_` prefix stripped).
- **Push.** `registerDevice({ provider, token, platform, appBundleId })`, `unregisterDevice(token)`, `listDevices()`, `setNotificationLevel(room, 'all' | 'mentions' | 'none')`, `muteConversation(room, muted?)`.
- **Messages.** `mentions` on `sendMessage()` (max 50); `messages.pin/unpin/listPins` and `messagePinned` / `messageUnpinned`; `messages.search({ q })`; `messages.threadPage(id, { cursor })` (`thread()` now returns the first page); `replyCount` / `lastReplyAt` on thread roots; `linkPreview` on messages. `messageUpdated` handlers receive a second argument `{ reason }` — `'link_preview'` when the server's unfurl lands, so it isn't shown as an edit.
- **Large and live rooms.** `presenceCount` event and `listPresence({ cursor, limit })`; `getPresence()` returns the first page. Audience tokens (`aud_room` claim): `chat.isAudienceViewer`, `connect()` joins the audience room by default, and member-only calls (inbox, read marks, push) reject locally with `NOT_A_MEMBER`.
- **`@swalvo/react`:** new hooks `useInbox`, `useConversation` (paging plus optimistic rows from the outbox), `useUnreadCount`, `usePresenceCount`, `useModeration`, and room-aware `useTyping` / `usePresence`; a headless UI kit — `<ChatProvider>`, `<ChannelList>`, `<MessageList>`, `<MessageComposer>`, `<Thread>` — unstyled by default with `className` hooks, plus an optional `@swalvo/react/chat/styles.css` using the Swalvo dark tokens. Existing `<SwalvoChat>` and its hooks are unchanged.
